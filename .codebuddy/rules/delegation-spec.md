# 仓库发配规范（Delegation Spec）

本规范约束 AI 在本仓库内的子代理发配、验收与来回用词。用户级技能（如 delegate-or-not）提供默认协议；本规范是仓库的最终事实源，两者冲突时以本规范为准。

## 分支与提交约定

- 提交一律由主线程执行；子代理只修改工作树，**禁止子代理执行 git commit/push**。
- 子代理产出提交信息：`[delegate:<task>] <摘要>`；主线程直接修改：`[main] <摘要>`。
- 隔离分支名：`delegate/<task>`；worktree 目录：`../wt-<task>`。

## 发配四步（每步以完成标准收尾）

1. **锁基线**：`git status --porcelain` 输出为空；记录 `git rev-parse HEAD` 的 SHA。
   完成标准：工作树干净，基线 SHA 已写入发配记录。
2. **发配**：提示词含四段——背景、目标、边界（白名单路径清单）、产出格式；**改代码类发配必须附《设计意图说明》**（当前版本见仓库根 AGENTS.md「设计意图」节），冲突即停手上报。
   完成标准：白名单与产出格式已逐字写入提示词。
3. **验收**：`git diff --stat` 对照白名单，逐项三查（越界、夹带、破坏）。
   完成标准：diff 全部落在白名单内，改动均有清单依据。
4. **归档**：通过则按提交约定由主线程提交；不通过则 `git restore .` 回滚到基线 SHA。
   完成标准：提交或回滚二选一已发生，工作树回到干净态。

大任务或并行发配改用 worktree：`git worktree add ../wt-<task> -b delegate/<task>`，验收 `git diff main...delegate/<task>`，通过 `git merge`，不通过删分支即可。

## 验证命令（验收第 3 步）

- **用户已授权 AI 执行 gradlew 构建验证**（2026-09-06 起）：
  - 编译检查：`gradlew :app:compileDebugJavaWithJavac`
  - 安装包构建：`gradlew :app:assembleDebug`（产物 app/build/outputs/apk/debug/）
- 验收手段：`git diff` 审查 + 构建验证 + 逐项对照修复清单。

## 报告用词（反引导协议）

- 每份来回报告按 `事实与证据 → 结论（含负面清单）→ 未决问题` 组织；结论锚定文件:行号、命令输出或 diff。
- "无问题"必须附验证手段（跑了什么命令、看了什么 diff）。
- 状态由验收产生：diff 审查通过才算完成，叙述措辞不产生状态。
- 禁止无证据评价性形容词（顺利/显著/基本完成/质量不错）；禁止预期式结论（应该没问题/理论上已修复）。

## 任务书格式（防泄露）

- 任务书只含确定性指令：背景、逐项指令（问题/位置/修法/验收标准）、勿动清单、完成标志。
- **禁止**出现：审核轮次与分级痕迹（如"MAJOR"/"PARTIAL→修"/"第 N 轮发现"）、执行者指派、裁决过程字样（"已裁决"/"倾向"/"二选一"）、过程统计（复现率等）。
- 括号仅允许用于技术参数与形态说明；流程信息一律留在主线程。

## 当前生效的管理规定
